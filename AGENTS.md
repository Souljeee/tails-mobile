# AGENTS.md

Инструкции ниже обязательны для всех AI-агентов, работающих в этом репозитории.
Они распространяются на корень проекта и все вложенные директории, если во вложенной директории
нет собственного `AGENTS.md` с более узкими правилами.

## Перед началом работы

1. Прочитай задачу, этот файл и [подробное руководство](docs/agent-development-guide.md).
2. Изучи соседние файлы и существующие тесты. Продолжай уже используемый подход, не создавай
   параллельную архитектуру без явной необходимости.
3. Проверь `git status` и не изменяй/не удаляй несвязанные пользовательские правки.
4. Сформулируй минимальный набор изменений, который полностью решает задачу.

## Непереговорные правила

- Архитектура — feature-first с направлением зависимостей
  `presentation -> domain/application -> repository -> data source`.
- UI-состояние и бизнес-сценарии реализуются через `Bloc` из `flutter_bloc`. Виджеты не обращаются
  напрямую к data source и не содержат бизнес-логику.
- Экранная навигация выполняется через типизированные маршруты `go_router` из
  `lib/src/core/navigation/routes.dart`. Не добавляй строковые пути и не используй
  `MaterialPageRoute` для новых экранов.
- Пользовательский интерфейс строится на компонентах, темах, цветах, типографике и assets из
  `lib/src/core/ui_kit`. Базовые layout-виджеты Flutter (`Row`, `Column`, `Padding`, `Sliver` и т. п.)
  допустимы. Перед созданием нового визуального компонента проверь UI kit; переиспользуемый
  компонент сначала добавь туда.
- Декомпозируй интерфейс в отдельные `StatelessWidget`/`StatefulWidget`, а не в методы вида
  `_buildHeader()`, `_buildContent()` или функции, возвращающие `Widget`. Метод `build` должен только
  декларативно компоновать небольшие виджеты. Нетривиальные секции выноси в именованные приватные
  классы виджетов.
- Не редактируй вручную сгенерированные файлы (`*.g.dart`, `*.gen.dart`, `*.tailor.dart` и другие
  generated-файлы). Меняй источник и перегенерируй код.
- Не добавляй новую зависимость, архитектурный слой или state-management подход, если задачу можно
  решить существующим стеком.
- Все пользовательские строки должны идти через локализацию, а визуальные значения — через токены
  UI kit, если соответствующий токен существует.
- Исправляй первопричину. Не оставляй заглушки, закомментированный код, `print`, игнорирование lint
  или молчаливое подавление ошибок без объяснимой причины.

## Проверка результата

После изменения Dart-кода запусти проверки, соразмерные изменению:

```sh
fvm dart format --line-length 100 <изменённые .dart файлы>
fvm flutter analyze
fvm flutter test
```

Если менялись аннотации, DTO, маршруты или иные codegen-источники:

```sh
fvm dart run build_runner build -d
```

Минимум для небольшого изменения — форматирование, анализ затронутого кода и релевантные тесты.
Если полную проверку запустить нельзя, явно укажи это в итоговом сообщении вместе с причиной.

## Завершение задачи

- Просмотри итоговый diff и убедись, что в нём нет случайных изменений.
- Добавь или обнови тесты для изменённого поведения.
- Кратко сообщи: что изменено, какие проверки пройдены и какие риски/ограничения остались.
- Подробные соглашения по архитектуре, BLoC, навигации, UI и тестированию находятся в
  [docs/agent-development-guide.md](docs/agent-development-guide.md).
