# План миграции UI «Хвостики» на Design 2.0 (v2, по PNG-макетам)

Код не изменялся. Версия 2 учитывает 7 PNG-макетов и ответы на вопросы v1.

## 0. Принятые решения

1. Тёмная тема остаётся, на временных цветах (светлые токены Design 2.0 зеркалятся, точные тёмные значения придут позже). Токены темы делаем так, чтобы значения dark подменялись в одном месте.
2. Онбординг-карусель на экране входа остаётся.
3. «Профиль» — пустой экран (заглушка сохраняется), дизайн позже.
4. Вес показывается в карточке списка питомцев.
5. Иконки типов событий назначаем сами (маппинг в разделе 6), финальные придут позже.
6. Макеты — PNG (7 экранов).

## 2. Что менять по экранам

**Общая оболочка (`scaffold_with_navbar.dart`).** Плавающая «пилюля» навигации (Питомцы/Календарь/Профиль; активная вкладка — accent-tint с иконкой и подписью accent) + отдельная круглая accent-кнопка «+» справа. Контент прокручивается под ними, значит нужен нижний inset (~96 pt) во всех списках вместо текущего `72+16` в календаре. «+» на разных вкладках: «Питомцы» — новый питомец, «Календарь» — новое событие, карточка питомца — вероятно новое событие для этого питомца **[уточнить]**.

**Вход.** Фото-шапка с нижними скруглёнными углами (xl), заголовок/подпись поверх фото с затемнением, индикатор страниц (точки, активная вытянутая); заголовок Display M; подпись ink-2; label «Номер телефона» над полем; поле с флагом, `+7`, разделителем и цифрами моноширинным; фокус — accent-обводка + внешнее кольцо accent-tint; текст согласия со ссылками (подчёркнуты); кнопка L 56 pt «Получить код →». Логика (`CodeTimerBloc`, маска, валидация) без изменений.

**Выбор породы.** Полноэкранная страница: chevron-back, заголовок по центру `Порода · кошки` (зависит от `petType`), поле поиска, строка «Метис или не знаю», секции по первой букве (заголовок Plex Mono CAPS), белые карточки с разделителями, выбранная порода — жирная + галочка accent, справа вертикальный алфавитный индекс. Заголовок нужно локализовать с учётом вида (кошки/собаки).

**Календарь.** Заголовок Display M + подпись «3 дела на сегодня» (mono); кнопка-пилюля «Сегодня» справа; «Сентябрь 2026 ⌄» + стрелки предыдущий/следующий вне карточки; чипы: «Все» (выбран — ink, залит) и питомцы с аватаром; карточка месяца (weekday и числа Plex Mono, выбранный день — accent-круг, под днями точки цветов питомцев); eyebrow «СУББОТА, 26 СЕНТЯБРЯ» + «3 события»; строки событий: слева время (`08:00` / «Весь день»), карточка с цветной полосой слева (цвет питомца), аватар питомца, заголовок, подпись `тип-иконка Тип · Питомец`, справа круглый чекбокс; выполненное — зачёркнуто, чекбокс pine. Логика блока/диапазона ±180 дней сохраняется.

**Мои питомцы.** Заголовок + mono-подпись «2 питомца · сегодня 3 дела», колокольчик (круг, accent-точка); карточка: крупное фото сверху со скруглением, плашка «● Собака» (точка цвета питомца), имя Display S + chevron, mono-строка `Порода · 2 года 8 мес. · 14,9 кг`, разделитель, блок ближайшего события (иконка в accent-tint, eyebrow «СЕГОДНЯ»/«ВЕСЬ ДЕНЬ», `17:05 · Прогулка в парке`). Пустое/ошибка/shimmer — по паттернам.

**Новое событие.** Sheet с ручкой: «Отмена» (accent) / заголовок; «Для кого» — чипы питомцев (выбран — ink); «Название»; «Тип» — горизонтальные чипы; «Дата» + «Время» рядом (иконки calendar/clock); «Повторение» — выпадающее с иконкой repeat; «Заметки · необязательно»; кнопка «Создать событие».

**Новый питомец.** Полный экран: «Отмена» / заголовок; круглая dashed-область фото с camera и accent-«+», «Добавить фото» + пояснение; секция «ОСНОВНОЕ»: «Вид» (две карточки-радио Кошка/Собака), «Кличка», «Пол» (две карточки-радио); секция «ДЕТАЛИ»: «Порода» (строка → страница выбора), «Дата рождения» + подсказка, «Вес» (поле с суффиксом «кг») и «Окрас» в две колонки, строка-переключатель «Стерилизована / Можно изменить позже в профиле»; кнопка «Добавить питомца» внизу.

**Карточка питомца.** Фото на всю ширину с круглыми кнопками (назад, ✎ изменить, ⋯ меню), «лист» с верхним скруглением поверх фото; имя Display M, тег «● Собака · Алабай»; статистическая полоса `ВОЗРАСТ | ВЕС | ПОЛ`; сегмент-контрол `Обзор / Здоровье / События`; секция «ОСНОВНОЕ» (+ «Изменить») со строками Дата рождения, Порода, Окрас, Кастрирован; «БЛИЖАЙШИЕ СОБЫТИЯ» (+ «Все») с чекбоксами; «ЗДОРОВЬЕ» (+ «Открыть») с 4 плитками (Прививки, Лекарства, Вес, Ветеринар). Внизу та же пилюля навигации и «+».

## 8. Где дизайн затрагивает UX, данные или бизнес-логику (требует решения)

1. **Вес в списке питомцев.** `PetDto`/`PetModel` списка не содержат `weight` (есть только в `PetDetailsDto`). Варианты: (а) backend добавляет `weight` в ответ списка — правим DTO/модель; (б) до этого показываем строку без веса (поле nullable). Запрос N+1 к деталям не рекомендую.
2. **«Ближайшее событие» в карточке питомца и подписи «сегодня 3 дела».** Данных на экране питомцев сейчас нет. Решение без API: `ScheduleRepository.getScheduleEvents(...)` уже возвращает события по диапазону; добавить bloc/use-case на экране питомцев, который берёт события на ближайшие N дней и считает «следующее на питомца» и число дел сегодня. Это новый state-management-кусок, а не только UI.
3. **Тип события.** Сейчас `type` жёстко `custom` (в форме нет выбора). Макет добавляет чипы типа (Прогулка, Кормление, Лекарства, «Вр…» — обрезано). В enum 12 значений, в макете, вероятно, 4–5 групп. Нужно: полный список чипов и соответствие enum (например, «Лекарства» → `dailyPills` или `weeklyPills`?). API не меняется, но выбор влияет на данные.
4. **«Метис или не знаю».** Такого элемента в списке пород API нет (`BreedModel{id,name}`), а `breedId` обязателен для добавления. Нужен либо специальный `id` на backend, либо решение «породу можно не указывать» (изменение валидации формы). Пока — не реализовывать логику, только оформить строку, если сервер вернёт такую породу **[решить]**.
5. **Вес — поле ввода `0,0 кг` вместо пикера.** Сейчас `WeightPicker` (`flutter_picker_plus`, bottom sheet). Замена на числовой ввод меняет UX и добавляет валидацию (запятая/точка, диапазон). Можно оставить пикер, открывающийся по тапу на поле, — тогда визуальное изменение.
6. **Обязательность полей.** Подсказка «Фото можно добавить позже, остальные поля обязательны» соответствует текущей валидации (`image` необязателен). Подпись «Стерилизована» в макете статична; в l10n сейчас «Кастрирован» — подпись зависит от пола? **[уточнить]**.
7. **Вкладки «Здоровье» и «События» и раздел «ЗДОРОВЬЕ» (Прививки, Лекарства, Вес, Ветеринар).** В приложении нет ни модели, ни API для медзаписей. Макеты содержат только «Обзор». Предлагаю: реализовать «Обзор» полностью, сегмент-контрол показать, а «Здоровье»/«События» — временно без контента (или скрыть) до появления backend/дизайна. Плитки «Нет записей» — не хардкодить как реальные данные. «Вес» на плитке — реальное значение из питомца. «Ближайшие события» питомца — фильтр расписания по `petId` (данные есть).
8. **Навигация карточки питомца.** На макете карточка питомца показывает плавающую навигацию и «+», то есть открывается внутри вкладки «Питомцы», а не поверх (сейчас `MaterialPageRoute` вне `go_router`). Для этого нужны типизированные маршруты (`/pets/:id`, вложенные в `PetsBranch`) — это единственный обоснованный случай переработки навигации ради дизайна. Аналогично полноэкранная «Порода» и «Новый питомец» (через маршруты, результат возвращать через `pop`/extra).
9. **Кнопка «⋯» вместо «удалить».** Кнопки удаления в шапке больше нет: «Изменить» (✎ и ссылка «Изменить»), удаление — вероятно в меню «⋯». Сохранить подтверждение (`DeletePetBottomSheet`) и обработку ошибок.
10. **Колокольчик с accent-точкой.** Сейчас кнопка без действия; точка означает непрочитанные уведомления, логики нет. Пока — без точки или статично выключенная; решить вместе с продуктом.
11. **Возраст.** Список: «2 года 8 мес.» (полная форма), детали: «2 г. 8 мес.» (краткая) — нужны две ARB-формы с плюрализацией (год/года/лет) и единый корректный расчёт (сейчас `дни÷365 / 30` продублирован в двух файлах). Вес — с запятой: `14,9 кг` (сейчас `'$weight кг'` даёт точку).
12. **Кнопка «Сегодня» и выбор месяца** («Сентябрь 2026 ⌄»): новое поведение календаря (прыжок на сегодня, пикер месяца/года). «Сегодня» — простое действие, пикер месяца дизайна нет.
13. **Точки под днями календаря** — данные есть (`scheduleEvents`), цвет по палитре питомцев; для «Все» — до N точек по разным питомцам. Правила ограничения точек уточнить.
14. **Пилюля навигации перекрывает контент** — во всех скроллах нужен нижний inset; иначе последний элемент недоступен.
15. **Accessibility.** `textScale` до 2× (уже поддерживается приложением) — макеты с фиксированными высотами (плашки, чипы 50 pt, шапка 320 pt) надо делать адаптивными; чекбокс/чипы ≥ 44 pt.

## 9. Порядок реализации

**Этап 0 — Основа.** Шрифты; токены (цвета/типографика/spacing/radius/shadow/motion) + `build_runner`; иконки в `UiAssets`; `ThemeData`; `PetColors` и форматтеры возраста/веса (с тестами).

**Этап 1 — UI kit** (небольшие PR): `UiButton` → `UiTextField`/`UiFormField` → `UiCard`, `UiChip`, `UiPetTag`, `UiIconBadge`, `UiIconButton` → `UiFloatingNavBar` + `UiFab` → `UiCheckbox`/`UiRadio`/`UiSwitchRow`/`UiSelectableCard`/`UiSegmentedControl` → `UiBottomSheet`/`UiSheetHeader`/app bar → `UiEmptyState`/`UiSnackBar`/shimmer → календарь (`MonthCalendar` рестайл) → `UiEventTile`, `UiInfoRow`/`UiGroupedList`, `UiStatStrip`, `UiAlphabetIndex`, `UiHeroCarousel`, `UiPhoneField`.

**Этап 2 — Экраны:**
1. Оболочка: плавающая навигация + FAB + нижний inset (заодно пустой «Профиль»).
2. Вход и ввод SMS-кода.
3. Календарь (данные уже есть; проверка kit на реальном экране).
4. Новое событие (sheet) + выбор типа (после решения п. 8.3).

**Поведение навигации на карточке питомца.** На корневых экранах (Питомцы, Календарь, Профиль)
внизу — «пилюля» вкладок и отдельная кнопка «+». При переходе на карточку питомца «пилюля»
анимированно растягивается на всю ширину (до полей экрана), а кнопка «+» исчезает; при возврате
происходит обратная анимация и кнопка появляется снова. Технически: оболочка (`ScaffoldWithNavBar`)
знает, находится ли активная ветка на корневом маршруте, и строит `UiFloatingNavBar` с анимацией
между двумя состояниями (`AnimatedContainer`/`AnimatedSize`, 300 ms; при «reduce motion» — без анимации).
Состояние берётся из go_router (текущий location), без нового state-management. Сама карточка
использует нижний inset под растянутую панель.
