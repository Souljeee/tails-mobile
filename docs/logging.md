# Логирование

Документ описывает, как устроен журнал приложения «Хвостики», что попадает в него автоматически и
когда нужно добавлять записи вручную. Правила для агентов и разработчиков — в разделе 4;
краткая версия правил продублирована в `AGENTS.md`.

## 1. Зачем и главные принципы

Журнал нужен, чтобы по присланным логам восстановить, что происходило в приложении у пользователя
перед сбоем: куда он переходил, какие запросы уходили, какие события обрабатывали блоки.

- **Один способ писать логи.** Весь код использует фасад `TailsLogger`. Прямые вызовы `print`,
  `debugPrint`, `developer.log` и `package:logger` в приложении запрещены. `package:logger`
  импортируется только в `core/logging/sinks/` (это проверяет `logging_architecture_test.dart`).
- **Данные очищаются автоматически, но не доверяй этому слепо.** Санитайзер скрывает токены, пароли,
  коды и телефоны, но свободный текст защищён только регулярками. Личные данные в сообщение не
  пишутся.
- **Журнал не ломает приложение.** Сбой sink'а, файла или Sentry не должен приводить к исключению
  в бизнес-коде.
- **Одна ошибка — один отчёт.** Ошибка отправляется в Sentry ровно один раз, даже если её видели
  несколько слоёв.
- **Приложение не отправляет журнал само.** Файл на устройстве уходит на сервер только по явному
  выбору пользователя в «Обратной связи».

## 2. Архитектура

```text
код приложения ──► TailsLogger (статический фасад)
                       │
                       ▼
                TailsLogDispatcher ── санитизирует message/data/error один раз,
                       │              изолирует сбои sink'ов
        ┌──────────────┼───────────────┬──────────────────┐
        ▼              ▼               ▼                  ▼
  ConsoleLogSink  ErrorReporterSink  BreadcrumbLogSink  FileLogSink
  (консоль,       (ошибки → Sentry,  (breadcrumbs →     (файлы журнала
   package:logger) дедупликация)      Sentry)            с ротацией)
```

Каталог `lib/src/core/logging/`:

| Файл | Назначение |
| --- | --- |
| `tails_logger.dart` | Фасад и диспетчер: `trace/debug/info/warning/error/fatal`, `configure`, `reset`, `isEnabled`. |
| `tails_log_event.dart` | Запись журнала, уровни (`TailsLogLevel`) и категории (`TailsLogCategory`). |
| `tails_log_config.dart` | Пороги и лимиты по режимам сборки. |
| `tails_log_sanitizer.dart` | Очистка секретов, телефонов и длинных значений. |
| `tails_log_formatter.dart` | Однострочный формат записи. |
| `tails_log_sink.dart` | Интерфейс получателя записей. |
| `tails_log_context.dart` | Идентификатор запуска, текущий экран, BLoC-инициатор работы. |
| `tails_loggable.dart` | Интерфейс `TailsLoggable` для событий и состояний с безопасными данными. |
| `log_exporter.dart` | Сборка файлового журнала в gzip для обращения в поддержку. |
| `sinks/` | `ConsoleLogSink`, `ErrorReporterSink`, `BreadcrumbLogSink`, `FileLogSink`. |
| `integrations/` | Автоматические источники записей (раздел 3). |

Фасад статический, потому что журнал нужен ещё до сборки зависимостей (запуск, глобальные
обработчики ошибок). Подключается один раз в `AppRunner.startup()`; в тестах — через
`TailsLogger.configure(sinks: [...])` и `TailsLogger.reset()`.

## 3. Что логируется автоматически

Эти записи писать вручную не нужно.

| Источник | Категория | Что пишет |
| --- | --- | --- |
| `LoggingHttpClient` | `network` | Запрос `→ #42 GET /pets/ screen=pets bloc=PetsBloc#1c`, ответ `← #42 200 … 138ms 3.4KB`, ошибку `✕ #42 …`. Заголовки очищаются, тела JSON обрезаются. |
| `TailsBlocObserver` | `bloc` | Создание и закрытие, события, переходы состояний (`Loading → Success ‹FetchRequested›`), ошибки блоков. |
| `NavigationLogger` | `navigation` | Переходы `from → to`, шаблон пути, параметры; модальные окна по имени. |
| `AppStartLogger` | `app` | «Приложение запущено»: версия, сборка, окружение, платформа, ОС, модель, идентификатор запуска. |
| `AppLifecycleLogger` | `app` | Смена состояния приложения (`resumed → inactive`). |
| `CompositionRoot` | `app` | Тайминги шагов инициализации. |
| `AppRunner` | `app` | «Первый кадр отрисован» с временем от старта; `fatal`, если инициализация упала. |
| `GlobalErrorHandler` | `app` | Необработанные ошибки Flutter, платформы и зоны. |

Подробности:

- **Сеть.** Клиенты оборачиваются в `LoggingHttpClient` в `CompositionRoot` (`public`,
  `auth-refresh`, `api`, `api-retry`). Тела запросов и ответов пишутся во всех режимах сборки
  (санитизированные, обрезанные до `networkBodyMaxLength`), но в Sentry не уходят. Multipart —
  только имена полей и размеры.
- **BLoC.** В записи попадают только имена типов событий и состояний. Содержимое добавляется
  точечно через `TailsLoggable` (раздел 6).
- **Корреляция BLoC → сеть.** Обработчики событий выполняются в зоне с идентификатором блока
  (`SequentialBlocTransformer`), поэтому запрос подписывается `bloc=PetDetailsBloc#a3`. Блок
  помечается в момент создания, поэтому `on<Event>` нужно вызывать в конструкторе.
- **Текущий экран** хранится в `TailsLogContext.screen` и добавляется в записи запросов.

## 4. Когда добавлять логирование вручную

Автоматика покрывает сеть, навигацию, жизненный цикл и блоки. Вручную пишутся события, которые она
не видит.

### Нужно писать

- **Шаги ключевых пользовательских сценариев**, если по ним позже придётся восстанавливать
  картину: вход и выход, удаление аккаунта, создание/удаление питомца и события, смена настроек
  уведомлений. Категория `business`, уровень `info`.
- **Решения и ветвления без сетевого вызова и без смены состояния блока**, которые меняют
  поведение: «токен не обновился → выход из аккаунта», «push-разрешение отклонено», «устройство
  отвязано».
- **Фоновые операции и интеграции**: регистрация push-токена, обработка уведомления, синхронизация
  в фоне, работа с платформенными каналами и локальным хранилищем.
- **Подавленные ошибки.** Если код ловит исключение и продолжает работу (`catch`, запасной путь,
  `unawaited`), его нужно записать как `warning` или `error`. Молчаливое `catch` запрещено.
- **Ошибки, которые никто выше не увидит**: в репозитории, который не пробрасывает исключение в
  блок, и в фоновых потоках.
- **Нештатные состояния**: данные пришли в неожиданном формате, неизвестное значение enum,
  деградация на запасной вариант.

### Не нужно писать

- Каждый запрос, переход и событие блока: они уже в журнале.
- Содержимое UI: нажатия кнопок, перерисовки, анимации. Исключение — действие, которое запускает
  сценарий без блока и сети, и это важно для разбора.
- Циклы и частые события (скролл, ввод текста, таймеры). Если запись нужна, используй `trace` и
  проверяй `TailsLogger.isEnabled`.
- Дубли: если ошибку уже пишет `TailsBlocObserver`, `LoggingHttpClient` или `GlobalErrorHandler`,
  второй раз её не логируй.
- Персональные данные и любые секреты (раздел 7).

### Выбор уровня

| Уровень | Когда |
| --- | --- |
| `trace` | Подробности для глубокой отладки; в release не выводятся. |
| `debug` | Технические детали (события блоков, тайминги шагов). |
| `info` | Нормальные важные события: шаги сценария, переходы, запросы. |
| `warning` | Подозрительно, но сценарий не сломан: запасной путь, подавленная ошибка, ответ 4xx. |
| `error` | Операция не удалась. Уходит в Sentry, если не указано `report: false`. |
| `fatal` | Приложение не может продолжать работу (падение инициализации, необработанная ошибка зоны). |

### Выбор категории

`app` — запуск, жизненный цикл, инициализация, глобальные ошибки. `navigation` — переходы.
`network` — сетевой слой. `bloc` — блоки и кубиты. `business` — шаги пользовательского сценария;
используется по умолчанию.

## 5. Как писать запись

```dart
import 'package:tails_mobile/src/core/logging/tails_log_event.dart';
import 'package:tails_mobile/src/core/logging/tails_logger.dart';

// Шаг сценария: значения идут в data, а не в текст сообщения.
TailsLogger.info(
  'Питомец создан',
  source: 'PetRepository',
  data: {'petId': pet.id},
);

// Подавленная ошибка: пишем с ошибкой и стеком.
try {
  await _devices.unregister();
} on Object catch (e, s) {
  TailsLogger.warning(
    'Не удалось отвязать устройство',
    category: TailsLogCategory.app,
    source: 'PushNotificationsRepository',
    error: e,
    stackTrace: s,
  );
}
```

Правила записи:

- `message` — короткая неизменяемая фраза на русском. Переменные значения передавай в `data`
  (`ключ: значение`): так записи проще искать и санитайзер видит ключи.
- `source` — класс или компонент, который пишет (`PetRepository`). У записей BLoC и сети он
  заполняется автоматически.
- `error` и `stackTrace` передавай всегда, если есть исключение.
- `report: false` ставь, когда ошибку уже отправил другой слой или она ожидаема и не требует
  отчёта в Sentry. Сетевой слой поэтому пишет `report: false`: владелец отправки — блок.
- Перед сборкой дорогих данных проверяй `TailsLogger.isEnabled(level, category)`.
- Не вызывай `TailsLogger` из `TailsLogSink.write`: такие вызовы игнорируются, чтобы не получить
  бесконечную рекурсию.

### Формат строки

```text
2026-10-05 12:03:41.535 I NET  api  → #42 GET /pets/3/ screen=pet-details bloc=PetDetailsBloc#a3
2026-10-05 12:03:41.719 E BLOC PetDetailsBloc#a3  Ошибка
    ↳ ClientException(Connection timed out)
    #0 PetRepository.getPetDetails (...)
```

Время, уровень (`T D I W E F`), категория, источник, сообщение, поля `ключ=значение`, затем
исключение и стек отдельными строками с отступом. В консоли время без даты, в файле с датой.

## 6. События и состояния блоков: `TailsLoggable`

По умолчанию журнал блока содержит только имена типов. Чтобы по записи было видно, о каком
объекте речь, событие или состояние реализует `TailsLoggable`:

```dart
final class DeletePetEvent$DeleteRequested extends DeletePetEvent implements TailsLoggable {
  // ...
  @override
  Map<String, Object?> toLogData() => {'petId': id};
}
```

Что можно возвращать: идентификаторы, флаги, имена enum, счётчики. Что нельзя: имена, телефоны,
коды, тексты сообщений, содержимое форм, пути к файлам. События со вводом пользователя (например,
вход) намеренно не описывают себя.

## 7. Безопасность данных

Данные проходят санитайзер (`TailsLogSanitizer`) один раз, в диспетчере, до передачи sink'ам, и
ещё раз при экспорте журнала.

- Значения по ключам со словами `authorization`, `cookie`, `password`, `token`, `secret`,
  `apikey`, `credential`, а также `code`, `access`, `refresh`, `otp`, `pin` заменяются на
  `[REDACTED]`.
- Телефоны маскируются: `+79001112233` → `+7***2233` (по ключу и по шаблону в тексте).
- В тексте скрываются JWT, `Bearer …`, `Basic …` и пары `ключ=значение` с секретами.
- Строки обрезаются (2000 символов), глубина вложенности и число элементов ограничены.

Чего санитайзер не гарантирует: свободный текст защищён только регулярками. Поэтому:

- не вставляй в `message` значения из данных пользователя, передавай их в `data`;
- не логируй имена, адреса, тексты обращений, содержимое secure storage;
- если в DTO появился новый чувствительный ключ, добавь его в санитайзер
  (`extraSensitiveKeys` или список ключей) и тест `tails_log_sanitizer_test.dart`.

## 8. Ошибки, Sentry и дубли

Владелец отправки ошибки — тот слой, который знает больше всего:

| Источник ошибки | Кто отправляет в Sentry |
| --- | --- |
| Исключение в обработчике блока | `TailsBlocObserver.onError` (через `addError`) |
| Необработанная ошибка Flutter, платформы, зоны | `GlobalErrorHandler` |
| Ошибка сетевого запроса | Не отправляется сетевым слоем (`report: false`), отправляет блок |
| Ручной `error`/`fatal` | Сам вызов, если не указано `report: false` |

Поэтому ошибки репозиториев пробрасываются в блок, а блоки передают их в `addError(e, s)`. Не
перехватывай ошибку, чтобы только залогировать её и проглотить, если пользователь должен узнать о
сбое.

Защита от дублей: `ErrorReporterSink` не отправляет повторно ту же ошибку (по объекту ошибки и
тексту стека, окно 5 секунд, до 50 записей).

В Sentry попадают ошибки и breadcrumbs (записи от `info`). Тела запросов и данные сетевых записей
в Sentry не передаются. Дополнительно `SentryEventScrubber` очищает события и breadcrumbs перед
отправкой, а `sendDefaultPii` выключен. Сам журнал в Sentry не отправляется.

## 9. Режимы сборки и пороги

Пороги заданы в `TailsLogConfig.forBuildMode()`.

| Параметр | Debug | Profile | Release |
| --- | --- | --- | --- |
| Консоль | `trace` и выше | `debug` и выше | `warning` и выше; `network` — `info` |
| Файл | `debug` и выше | `debug` и выше | `debug` и выше |
| Breadcrumbs | `info` и выше | `info` и выше | `info` и выше |
| Отчёты об ошибках | `error` и выше | `error` и выше | `error` и выше |
| Тело запроса или ответа | 2000 символов | 1000 | 1000 |

Новые пороги добавляй в `TailsLogConfig`, а не в sink'и и не в места вызова.

## 10. Файловый журнал и отправка в поддержку

`FileLogSink` пишет журнал в приватную папку приложения (`getApplicationSupportDirectory()/logs`).

- Два файла: `tails_log.txt` (текущий) и `tails_log.1.txt` (предыдущий), каждый до ~1 МБ.
  Когда текущий заполнен, он становится предыдущим, а самый старый удаляется.
- Запись буферизуется и сбрасывается на диск раз в 3 секунды, сразу при `error` и `fatal` и при
  уходе приложения в фон. После падения доступен журнал предыдущего запуска.
- Журнал удаляется при выходе из аккаунта и при удалении аккаунта (`AuthRepository`,
  параметр `afterSessionCleared`).
- Сбои файловой системы не бросают исключений.

Отправка в поддержку:

1. Пользователь включает переключатель «Приложить журнал работы приложения» на экране «Обратная
   связь» (по умолчанию выключен; без файлового журнала скрыт).
2. `LogExporter` читает оба файла, повторно очищает каждую строку санитайзером и упаковывает в
   gzip. Если архив больше ~1,94 МБ, отбрасываются самые старые записи.
3. Архив уходит в `POST /feedback/` отдельным multipart-полем `logs` (`logs.txt.gz`).

Контракт бэкенда: поле `logs` необязательное, только на запись; `application/gzip`, внутри
UTF-8 текст; файл до 2 МБ и до 10 МБ после распаковки (иначе 413), не gzip — 400. Хранение
и сроки — в документации бэкенда.

До публикации в сторах в политике конфиденциальности должен быть пункт об отправке журнала.

## 11. Тестирование

- Для проверки записей используй `RecordingLogSink` (`test/helpers/recording_log_sink.dart`):

  ```dart
  setUp(() {
    sink = RecordingLogSink();
    TailsLogger.configure(sinks: [sink]);
  });
  tearDown(TailsLogger.reset);
  ```

- Проверяй, что в журнал попадает уровень, категория, сообщение и `data`, а секреты нет.
- Тесты `BlocObserver` создают блок после установки наблюдателя, а `Bloc.observer` и
  `Bloc.transformer` восстанавливают в `tearDown`.
- Тесты `FileLogSink` и `LogExporter` работают во временной папке.
- Для нового `TailsLoggable` добавь проверку `toLogData` в `loggable_events_test.dart`.
- Изменения санитайзера сопровождай тестом на конкретные ключи и шаблоны.

## 12. Как расширять

- **Новый получатель** (например, отправка в другой сервис): реализуй `TailsLogSink`, задай порог в
  `TailsLogConfig` и добавь в список в `AppRunner.startup()`. Код приложения менять не нужно.
- **Новая категория**: добавь в `TailsLogCategory` с короткой меткой; не заводи категорию под один
  вызов.
- **Новый источник автоматических записей**: добавь класс в `integrations/` и тест.
- **Замена `package:logger`**: затрагивает только `sinks/console_*`.

## 13. Известные ограничения

- Имена модальных окон (`DialogRoute`) в журнале навигации не заполняются; у `showUiBottomSheet`
  есть параметр `name`.
- Метка `bloc=` в записях запросов зависит от регистрации `on<Event>` в конструкторе блока.
- Свободный текст очищается только регулярками.
- Записи самых первых мгновений запуска (до инициализации движка) в файл не попадают: файловый
  журнал подключается после `WidgetsFlutterBinding.ensureInitialized()`.
